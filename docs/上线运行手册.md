# 拾器 AI 社区上线运行手册

## 当前交付与部署边界

应用功能、自动维护和本地回归已完成。本地预览使用项目自带的 PostgreSQL 17 开发启动器。尚未连接生产域名、生产数据库或真实邮件账号；本地验收不表示已经部署到公网，也不表示社区内容已经完成人工核验。

不自动填充“编辑实测”内容。运营需实际查看来源，执行要求复测的任务，并通过管理页记录当前版本的环境和证据，才能纳入精选。

## 生产配置

安装 Node.js 22+、PostgreSQL 17，并提供长期保存的上传磁盘。生产依赖用 `npm ci --omit=dev` 安装；本地 PostgreSQL 启动器和浏览器测试不随生产依赖安装。

关键环境变量：

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=4173
APP_ORIGIN=https://你的域名
DATABASE_URL=postgres://...
DATABASE_SSL=true
PASSWORD_PEPPER=至少32字符且长期固定的随机字符串
ADMIN_EMAIL=你的管理邮箱
ADMIN_PASSWORD=初始化强密码
ADMIN_NICKNAME=拾器运营
SEED_ON_START=false
UPLOAD_DRIVER=local
UPLOAD_DIR=/持久化磁盘/uploads
MAINTENANCE_ENABLED=true
WRITE_MAINTENANCE=false
TRUST_PROXY=false
EMAIL_PROVIDER=smtp
EMAIL_FROM=拾器 <no-reply@你的发信域名>
SMTP_HOST=你的SMTP服务器
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=...
SMTP_PASSWORD=...
```

数据库 SSL 根据数据库提供方要求设置；只有受信任反向代理正确覆盖客户端 IP 时才开启 `TRUST_PROXY`。密码 pepper 不应在重部署时重新生成。也支持 `EMAIL_PROVIDER=zeabur` 与 `ZSEND_API_KEY`，由现有邮件模块处理。

需要验证真实注册和重置邮件能送达；生产不会提供开发验证码。上传目录和数据库必须分别备份。站点目前面向单实例部署，限流为进程内状态，维护任务使用数据库租约避免重复运行。

## 发布步骤

1. 在隔离 PostgreSQL 17 中完成全部回归，并保留待发布的代码版本和依赖锁文件。
2. 暂停公开写入。已有新版可以用 `WRITE_MAINTENANCE=true` 重启；从旧版迁移时在反向代理启用维护页或停止旧应用写入口。
3. 使用 PostgreSQL 17 的 `pg_dump` 生成完整数据库备份；复制上传目录到独立备份位置。记录旧构建版本并验证备份可读取。
4. 对计划切换的数据库执行只读预览，保存输出中的待执行迁移与旧内容清单。
5. 执行迁移并保存报告。每个迁移文件在一个事务中应用，只有成功后才记录版本；失败先修复，不手工伪造 `schema_migrations` 记录。
6. 首次启动通过 `npm run db:seed` 创建配置中的管理员。初始化只创建账号，不添加公开资源。
7. 保持写维护模式启动新构建，确认健康检查、SSR 页面、静态资源与历史上传图片可用。旧内容应退出公共列表，作者、收藏和实际访问统计仍保留。
8. 通过管理员检查计划公开的 AI 内容。补齐领域、形态、用途与来源；确认纳入 AI 范围，重新核验后才恢复默认展示。
9. 完成检查后将 `WRITE_MAINTENANCE=false`，恢复公开流量与写入，验证真实注册、投稿、收藏、评论及问题反馈。

`npm start` 会执行未应用的数据库迁移。应提前运行迁移并评估报告，避免未经检查就在生产启动时变更结构。`npm run db:preview -- --report=报告文件路径` 仅预览；`npm run db:migrate -- --report=报告文件路径` 执行并保存结果。报告的上级目录须已存在。

## 回退

开放新版写入之前失败：停止新应用，恢复已验证的数据库及上传备份，切换旧构建，再做冒烟检查。

开放写入后出现问题：先进入维护模式并备份当前数据，保留新增投稿与关系。优先修复当前结构或执行经验证的兼容回退，不直接用旧快照覆盖数据库。不要删除未知上传文件或重置迁移记录。

## 冒烟检查

- `GET /api/health` 返回 200；首页、资源库、教程、专题和最近更新可直接打开与刷新。
- 无内容时展示空态；首批真实投稿后，列表、搜索和详情一致。
- 新投稿标记待验证；作者无法直接写编辑核验或精选字段。
- 实质修改生成新版本，封面修改不刷新核验时间，到期内容退出默认展示。
- 普通用户不能访问管理 API；私有内容不在公开 HTML、API 或 sitemap 中泄露。
- 旧片段地址转换正确，确认失效返回 410，缺失返回 404。
- 注册、重置邮件与上传磁盘均在真实部署环境验证。
- 运行维护命令后检查后台执行记录；异常入口进入人工核对，单次超时不自动下架。

## 日常运营

后台提供资源/教程管理、专题排序、复核队列、举报处理、链接异常、复现问题、用户、标签及维护任务记录。作者在个人中心查看自己的待复核提醒；编辑核验时填写具体版本和环境，避免“已经检查”这类无法追溯的说明。

首批可围绕建筑与室内、服装、编程 Agent、视频角色一致性、授权声音克隆、多语种配音和数字人口播组织专题。具体平台和版本在制作时确认，不将陈旧工具清单作为默认推荐，也不搬运第三方知识库正文。

上线后观察接口错误、页面加载、投稿失败、待复核数量、链接异常、收藏及真实外链点击。点击只代表访问外部入口，不表示已经完成任务。模型、工作流和媒体不由本站托管或执行；用户仍需遵守对应平台的访问条件。
